## Evidence and audit

Curated evidence is in `../../S1_anemia_cbc/runs/reference/2026-10-14-final/` and
`../../S2_brca_receptors/runs/reference/2026-10-14-final/`. Each export has its own
`EXPORT_MANIFEST.csv`; the event log, scripts, metrics, custom instructions and
failure evidence are retained. Exports omit registered input data, environment,

`summary.json` and `summary.csv` are generated by `scripts/check_acceptance.py`.
The auditor checks every exported manifest hash, forbidden paths and zero model
requests. Custom outcomes and failure categories are derived from exported logs
and `custom_instructions.md`, including instructions submitted before an early
failure. Instructions never reached after a failure are not counted as submitted.
Unknown values are not substituted with zero.

The source cards remain DRAFT. Actual local paths and prepared data are ignored.
Policy answers are attributed to `user:policy/<card hash>`, not measured human effort.
No AI Worker failure is replaced by a reference script: these runs have their own
explicit reference arm and no configured model.

## Development intervention and limitations

An initial proteome ER attempt was interrupted during a slow feature-question
review, then resumed after a metadata-review performance correction. The original
logs and interruption note remain local; the final result marks the resumption.
Its duration is the resumed invocation, not a fresh end-to-end timing measurement.
The question-source hash is recorded in the summary. Other final attempts were fresh.

Wide-table question review and output collection also take substantial time in these
development attempts. Invocation durations include that overhead and are not isolated
model-compute benchmarks.

Interpretation of wide omics tables can reach the existing 300-second step timeout.
Both HER2 tests exposed a reference bootstrap defect: a one-class resample
can return NaN in the current scikit-learn version, and strict JSON serialization
refuses it. Both are recorded as failures; no metric is fabricated or timeout
silently raised to obtain a successful outcome.

Reference execution cannot generate the requested custom scripts without a model.
Those instructions remain verbatim with explicit not-achieved outcomes. Therefore
core completion, when present, is distinct from full protocol completion.
